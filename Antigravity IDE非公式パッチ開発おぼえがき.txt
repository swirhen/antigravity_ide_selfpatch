================================================================================
Antigravity IDE 自己修正パッチ 開発メモ
================================================================================

対象: Antigravity IDE の Agent Side Panel
前提: クライアント側 JS を直接編集し、内部状態と UI の更新を制御する

--------------------------------------------------------------------------------
0. 目的と基本方針
--------------------------------------------------------------------------------
本プロジェクトは、Antigravity IDE のチャットペインに対して、以下の機能を追加・調整するための
自己修正パッチ開発メモである。

- セッション一覧ドロワー
- セッション名変更
- ピン留め/ピン解除
- 新規セッション開始
- セッションのアーカイブ/アーカイブ解除
- Enter 改行 / Ctrl+Enter 送信
- コロンコマンドの即時実行
- AI クォータ残量表示（Vitals）

本メモは「理想像」ではなく、現実の実装に基づいて整理する。内部 API や DOM 構造に依存する箇所は
明示的に実装依存として扱う。

--------------------------------------------------------------------------------
1. 実装済み機能
--------------------------------------------------------------------------------
1-1. セッション一覧ドロワー
- チャットペイン最上部にセッション一覧バーを表示する。
- 既定の開閉操作は F4 または :resume / :res で行う。
- ドロワー内では検索入力が可能。
- 検索履歴や各セッションのタイトルに対して、インクリメンタル検索が行える。
- 現在開いているセッションは優先順位が最上位になる。
- 優先順位は実装上、現在セッション > ピン留め > 更新時刻 で並び替えられる。
- 現在セッションの選択状態として、左側にアクティブな丸アイコンを表示する。
- ドロワー開閉時にフォーカスや選択位置を調整する。
- キーボード操作は ↑ / ↓ / Enter / Escape をサポートする。
- 3px 以上のマウス移動でのみ選択が更新されるガードを掛ける。
- 各セッションの右側にはピン操作と削除操作がある。
- 現在セッションを削除した場合は新規会話を開始する動作を行う。

1-2. セッションの名前変更
- :rename <名前> または :ren <名前> で即座に更新できる。
- F2 または 引数なしで :rename または :ren を入力した場合、現在のタイトルが事前入力されたダイアログが表示される。
- 意図しない AI 依頼を起こさず、自前のクライアント側更新を行う。
- 更新後はチャット入力欄へのフォーカス復帰を行う。
- 画面上のタイトルクリックでも rename を起動できる。

1-3. ピン留め
- F6 で現在のセッションをピン留めする。
- Ctrl + F6 でピン留め解除。
- :pin / :p と :unpin / :up でも実行可能。
- ピン留め状態はセッション一覧の並び順と表示に反映される。

1-4. 新規セッション
- Ctrl + F4 で新規会話開始。
- :new / :n でも新規会話開始。
- 実装上は、startNewConversation を呼び出して状態を切り替える。

1-5. セッションのアーカイブ/アーカイブ解除
- 各セッションのアイコンボタンからアーカイブ・解除が可能。
- :archive / :arc で現在のセッションをアーカイブ。
- :unarchive / :unarc で現在のセッションのアーカイブを解除。
- ドロワー最下部に「アーカイブ済み」セクションを折りたたみ表示（開閉状態は localStorage に保存）。

1-6. Enter 改行 / Ctrl+Enter 送信
- 既定の動作は「Enter 改行 / Ctrl+Enter 送信」である。
- ただし : で始まるコロンコマンドは Enter 1回で即時実行される。
- 設定画面で ON/OFF を切り替え可能。
- OFF の場合は通常のチャット挙動に戻る。

1-7. キーボードショートカット
- F4: セッション一覧開閉
- F2: セッション名変更
- F6: ピン留め
- Ctrl + F6: ピン解除
- Ctrl + F4: 新規セッション
- これらは antigravity.session.* として登録される。
- 実際の割り当ては keybindings.json で変更可能な設計である。

1-8. 設定ダイヤログ


1-9. AI クォータ残量表示（Vitals）
- AI クォータ残量とステータスを入力欄周辺に表示する。
- 5h / 7d の残量を表示する。
- 10% 未満は赤、25% 以下は黄、通常時は緑で表示する。
- ホバー時に詳細のポップアップを表示する。
- Gemini / Claude などの稼働状況も表示する。
- 7日枠の残量を基に pace 判定を行う。

2. 実装アーキテクチャ
--------------------------------------------------------------------------------
2-1. 独立モジュール
- ファイル名: antigravity-session-patch.js
- 本体の JS に直接組み込まれるロジックを、独立モジュールとして保守可能な形に分離している。
- ここでは以下を管理する。
  - 設定管理
  - セッション一覧UI
  - キーボード処理
  - rename ダイアログ
  - コロンコマンド判定
  - Vitals バッジ

2-2. 自動適用スクリプト
- ファイル名: apply_patch.py
- 役割: antigravity-session-patch.js を読み込み、workbench.desktop.main.js の先頭へ安全に注入する。
- 併せて以下を処理する。
  - フックの挿入
  - 既存パッチの更新
  - product.json の整合性確認
  - keybindings.json への登録
- 実装上は、実行時に動的ロードを行わず、バンドル注入方式を採用している。

2-3. ディレクトリ構成

├── antigravity-session-patch.js
├── apply_patch.py
├── rollback.py
├── README.md
├── Release.md

└── Antigravity IDE非公式パッチ開発おぼえがき.txt

--------------------------------------------------------------------------------
3. 前提条件と実装依存
--------------------------------------------------------------------------------
本実装は Antigravity IDE の内部構造に対して直接触るため、以下を前提として扱う。

- 本体の workbench.desktop.main.js を破壊的に改変している。
- DOM の構造や CSS クラス名は IDE 本体バージョン依存である。
- セッション一覧、本体タイトル、ピン状態、削除処理は内部状態へ依存する。
- 例: trajectorySummariesProvider, cascadeContext, startNewConversation, updateConversationAnnotations など。
- 画面の表示は IDE の内部変数とイベント設計に依存している。
- Vitals はローカルの Language Server API に依存している。
- 設定保存は localStorage を使用する。
- keybindings.json と product.json の整合性を保つ必要がある。

このため、アップデートや IDE の差分変更が発生した場合、挿入位置や配列順序の調整が必要になる。

--------------------------------------------------------------------------------
4. 実装上の注意点
--------------------------------------------------------------------------------
4-1. 依存関係
- 画面上のセッション一覧の取得は内部状態から行われる。
- UI の見た目とロジックが内部 state に強く結び付いている。
- そのため「見た目の変更」だけではなく、取得元と更新元を同時に確認する必要がある。

4-2. 動作保証の仕組み
- apply_patch.py がパッチの注入とバックアップを担う。
- 変更前に本体のバックアップを作成する。
- 既存のパッチが残っている場合は更新を行い、差し替え処理を行う。

4-3. 変更時のルール
- 一度に大きな変更をまとめて行わない。
- 変更ステップごとにバックアップを作成する。
- 変更後は、最小限の確認を行い、動作の差分を記録する。

--------------------------------------------------------------------------------
5. 開発時のバックアップ方針（AI向け）
--------------------------------------------------------------------------------
本プロジェクトでは、Antigravity IDE の本体ファイルを書き換えるため、各作業ステップでバックアップを必須とする。

必須バックアップ対象:
- workbench.desktop.main.js
- product.json
- keybindings.json
- antigravity-session-patch.js
- 変更前後の差分ファイル

必須ルール:
- 実装前に必ず現在の状態を保存する。
- 1 ステップごとにバックアップを作成する。
- 変更が失敗した場合は、直ちにバックアップから復元する。
- IDE が起動しない、再起動後に動かない、画面が崩れる場合は、まずバックアップを確認し、ロールバックを行う。
- 「保存してリロード」だけで直ると判断しない。
- 本体が壊れた場合に戻せる体制を前提に作業を進める。

ロールバックの基本方針:
- 変更前の本体ファイルを復元する。
- 既存のパッチを消して初期状態へ戻す。
- 必要なら再度 patch を再適用して比較する。

--------------------------------------------------------------------------------
6. ロールバックと再適用
--------------------------------------------------------------------------------
6-1. ロールバック
- 元の状態に戻す場合は、バックアップ済みの本体ファイルを復元する。
- 破損している場合は、workbench.desktop.main.js.backup_before_patch を利用する。
- 必要に応じて product.json と keybindings.json も元に戻す。

6-2. 再適用
- IDE のアップデート後や本体が置き換わった場合は、apply_patch.py を再実行する。
- 実行後に Developer: Reload Window を実施する。
- その後、挙動確認とバックアップ再生成を行う。

--------------------------------------------------------------------------------
7. まとめ
--------------------------------------------------------------------------------
本パッチは、Antigravity IDE の内部状態と UI を直接触る非公式パッチであり、
「機能追加」だけでなく「安全な復元」が非常に重要である。

今後の開発では、以下を常に意識する。

- 実装の対象は Antigravity の内部 API と DOM である。
- 機能要件と内部依存を分けて管理する。
- バックアップを必須とし、破損時に戻せるようにする。
- 変更ごとに差分と挙動確認を残す。

これが、アップデート耐性とメンテナンス性を確保する最大の基盤となる。
